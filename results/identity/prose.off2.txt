`mmap` and `read` differ fundamentally in how they handle data transfer between disk and memory: `read` explicitly copies data from the file into a user-space buffer provided by the application, requiring manual management of buffer sizes and multiple system calls for large files, whereas `mmap` maps the file directly into the process’s virtual address space, allowing the operating system’s page cache to lazily load only the pages actually accessed into physical memory. This means `mmap` avoids explicit copying overhead and simplifies code by treating the file as a memory array, but it introduces complexity around memory management (e.g., handling `MAP_PRIVATE` vs. `MAP_SHARED`), potential performance penalties from page faults on random access patterns, and the need to explicitly unmap the region, while `read` is more predictable for sequential streaming but incurs higher CPU and memory bandwidth costs due to repeated copying.
